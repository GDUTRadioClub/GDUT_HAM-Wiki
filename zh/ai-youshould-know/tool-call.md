# Tool Call：工具调用

> **一句话解释**：Tool Call 让模型按约定格式请求调用外部函数或 API，再把执行结果返回给模型继续推理。

---

## 为什么需要 Tool Call？

大语言模型本身只会生成文本，它不能直接：

- 查询实时天气；
- 读取数据库；
- 发送邮件；
- 操作浏览器；
- 调用公司内部系统。

Tool Call（也叫 Function Calling）提供了一种结构化方式，让模型可以“请求”外部程序执行这些动作。

---

## 一次 Tool Call 的完整流程

```text
用户提问
   ↓
模型判断需要工具
   ↓
模型输出结构化调用请求（工具名 + 参数）
   ↓
外部程序执行工具
   ↓
把工具结果返回给模型
   ↓
模型结合结果生成最终回答
```

关键点：**真正执行工具的是外部程序，不是模型本身。**

---

## 一个直观例子

用户问：“北京现在天气怎么样？”

模型可能输出：

```json
{
  "tool": "get_weather",
  "arguments": {
    "city": "北京",
    "unit": "celsius"
  }
}
```

外部程序调用天气 API，得到：

```json
{
  "temperature": 26,
  "condition": "多云"
}
```

模型再把它变成自然语言回答：“北京现在 26℃，多云。”

---

## Tool 的定义通常包含什么？

- **名称**：唯一标识，例如 `get_weather`；
- **描述**：告诉模型这个工具能做什么、什么时候用；
- **参数 schema**：参数名、类型、是否必填、取值范围；
- **返回值**：工具执行后的数据结构。

描述和 schema 越清晰，模型越不容易乱调用。

## Tool Call 与 MCP、Skill 的关系

| 概念 | 层级 | 关注点 |
|------|------|--------|
| Tool Call | 模型调用机制 | 模型如何请求执行函数 |
| MCP | 接入协议 | 工具/数据如何标准化暴露 |
| Skill | 能力封装 | 如何把流程、知识和工具组合成可复用技能 |

简单理解：

- Tool Call 是“打电话”；
- MCP 是“电话网络标准”；
- Skill 是“一套完整的话术和办事流程”。

---

## 安全与工程实践

- **权限最小化**：只允许调用必要工具；
- **参数校验**：不要直接信任模型生成的参数；
- **人工确认**：删除、支付、发消息等高风险操作应二次确认；
- **超时与重试**：外部 API 可能失败，需要健壮处理；
- **审计日志**：记录工具调用链，便于排查问题；
- **注入防护**：外部内容可能诱导模型调用危险工具。
