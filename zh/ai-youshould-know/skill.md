# Skill：AI 技能

> **一句话解释**：Skill 是可复用的能力包，把提示词、工具调用流程和领域知识封装起来，让 Agent 不必每次从零解决同类任务。

---

## Skill 是什么？

在 AI Agent 语境中，Skill 通常指一组 **可被复用的能力封装**，可能包括：

- 系统提示词或角色设定；
- 任务步骤和决策规则；
- 需要调用的工具或 MCP Server；
- 领域知识、模板和示例；
- 输出格式与质量检查标准。

一个 Skill 可以理解为“教 Agent 如何完成某类任务的操作手册 + 工具箱”。

---

## 为什么需要 Skill？

如果没有 Skill，用户每次都要重新描述：

- 背景是什么；
- 按什么步骤做；
- 用哪些工具；
- 输出成什么格式；
- 哪些事情不能做。

Skill 把这些经验沉淀下来，带来：

- **一致性**：同类任务输出稳定；
- **复用性**：团队成员共享同一能力；
- **可维护性**：规则集中更新；
- **安全性**：限制工具权限和操作边界。

---

## Skill 与 Tool 的区别

| 概念 | 回答的问题 | 例子 |
|------|-----------|------|
| **Tool** | “能做什么操作？” | 搜索网页、执行 SQL、发送邮件 |
| **Skill** | “如何完成一类任务？” | 竞品调研、周报生成、代码审查 |

Tool 是原子能力；Skill 是围绕目标组织起来的流程与知识。

一个 Skill 可以调用多个 Tool，也可以包含多个子 Skill。

---

## Skill 的典型结构

```text
Skill
├── metadata：名称、描述、版本、适用场景
├── instructions：任务步骤与决策规则
├── tools：允许调用的工具/API
├── knowledge：领域资料与示例
├── templates：输出模板
└── evaluation：质量检查与测试用例
```

---

## 生活中的类比

- **Tool** 像是厨房里的刀、锅、烤箱；
- **Skill** 像是一份菜谱，告诉你先做什么、后做什么、火候如何；
- **Agent** 像是厨师，根据菜谱和目标决定实际动作。

---

## 设计一个好 Skill 的原则

1. **目标清晰**：说明什么情况下使用、解决什么问题；
2. **步骤可执行**：避免模糊描述，尽量给出明确动作；
3. **权限最小化**：只开放完成任务必需的工具；
4. **输出可验证**：定义格式、字段和质量标准；
5. **可迭代**：记录失败案例并持续更新。
